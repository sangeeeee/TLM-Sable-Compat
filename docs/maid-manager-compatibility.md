# Maid Manager 锚点兼容

适配版本：TLM Maid Manager `1.0.3-beta2`，Minecraft `1.21.1` / NeoForge；本模组版本仍为 `0.0.1-beta`。

## 使用方法

按 Maid Manager 原本的方式放置、命名锚点，然后从管理平板选择女仆并派遣到锚点。锚点可以位于普通世界或 Sable 结构上；精确日程中的指定锚点传送也使用相同处理。

- 管理列表保存方块地址，不缓存移动结构的世界投影。打开界面后结构继续移动，传送仍使用点击处理时的结构姿态。
- 优先寻找锚点顶部，其次检查水平三格以内的邻近落点。候选必须有支撑、足够的身体空间，属于锚点所在空间，并通过普通世界及其他结构的碰撞检查。
- 没有安全落点、结构倾斜过大、锚点不存在或未加载时，传送失败，保留原位置和 Home。不会为了传送从旧序列化指针恢复已经收纳或删除的结构。
- 支持普通世界与结构之间、结构之间以及维度之间派遣。跨维度后在实际抵达的新女仆实体上设置结构跟踪和 Home。
- 未配置河童罗盘时，成功派遣会启用以锚点为中心的简单 Home，随结构移动。沿用本模组已有的 Home 卸载、分裂和移除规则。
- 已配置河童罗盘时，同维度、同空间且有效的活动区保持不变；不会把三活动区覆盖成锚点 Home。罗盘属于另一结构、另一维度或已失效时，拒绝派遣，需要先清除或重新绑定罗盘。
- 命名记录在结构装配、分裂的实际方块搬运过程中更新，女仆的简单 Home 跟随锚点所在碎片。搬运前已经打开的界面需要刷新后再选择新的方块地址。

## 实现范围

本次覆盖管理界面的锚点派遣，以及精确日程中的指定锚点传送。保留管理平板、女仆所有权、锚点命名记录等原有服务端检查；没有将 Maid Manager 变成必装依赖。显示的结构坐标是稳定的局部方块地址。

Maid Manager 当前版本自身已有 Sable 适配。本模组衔接并修正以下部分：

1. 列表使用世界投影，船移动后传回的坐标可能无法匹配原锚点。
2. 装配只移动记录索引、没有更新记录内的持久化地址；分裂时也不能将旧结构局部坐标当成世界坐标求逆。
3. 原落点仅检查空气且失败时仍返回原坐标，没有完整的碰撞与空间检查。
4. 原管理器持续更新世界 Home，与本模组的局部 Home 冲突。
5. 跨维度传送会创建新实体，必须给目标维度中的实际实体设置状态。

搜索仅在派遣时执行，没有新增每 tick 锚点扫描。其它平板功能、投影器、灵魂锚饰品和“传送到主人”等功能未在本次宣称完成专门适配。

## 验证

使用 `./gradlew -PmanagerTests runGameTestServer` 加载 Maid Manager；默认仍仅编译依赖。新增服务器测试覆盖实际派遣处理、移动/旋转后的列表地址、Home、封闭落点、移除结构、罗盘冲突、倾斜、装配保存/读取、分裂和跨维度往返。客户端管理界面的显示及完整整合包操作仍需游戏内验证。
