# 寻路与 Home：第一阶段

实现基于 Minecraft 1.21.1、NeoForge 21.1.248、Touhou Little Maid 1.5.3、Sable 2.0.5 的实际类与接口。

## 跟随

主人所在空间直接读取 `Sable.HELPER.getTrackingSubLevel`，不额外用距离、脚下射线或创造飞行状态推断结构。Sable 保持跳跃期间的结构跟踪时，兼容层也保持该结构目标。

| 场景 | 行为 |
| --- | --- |
| 双方均在普通世界 | 使用女仆原有跟随分支 |
| 双方在同一结构 | 沿局部坐标路径跟随；保持原有起步距离、速度和停止距离 |
| 主人在 B，女仆在 A 或普通世界 | 仅搜索 B 上主人附近的安全落点并传送，不规划 A 到 B 的路径 |
| 主人未被任何结构跟踪 | 不搜索附近结构；有足够距离且原世界落点安全时才传送 |
| 没有合格落点 | 定期重试；不清除女仆独立的工作或闲逛移动目标 |
| 开启 Home、坐下、睡觉、被拴住或乘坐 | 保留原女仆相应的跟随限制 |

同结构距离沿用女仆的限制半径：开始跟随为半径减 2，远距传送为半径加 2，默认分别为 6 和 10 格。跨结构进入主人当前结构不要求达到此距离。每轮最多随机检查 10 个落点，失败后间隔 20 tick 重试。因此小甲板上的可用位置可能要经过数轮才被选中。

落点必须位于所选空间，具有可靠顶面支撑和完整的身体空间，避开女仆禁止传送的方块、脚部流体和世界边界。同时检查其他结构的碰撞；没有允许踩墙或倒挂行走的能力。

原版维度切换仍由女仆模组的原有机制管理。本阶段没有新增跨维度寻路、强制加载远端结构或悬空救援能力。

## Home 与罗盘

GUI 在结构上设置 Home 时记录女仆局部位置及其支撑锚点。开启 Home 后不跟随主人。工作、闲逛和睡眠区域使用原有日程及范围配置；返回活动区保留女仆原有的近距离步行、远距离尝试传送的行为。

河童罗盘第一次记录时固定空间。后续只能记录同维度的同一普通世界或同一结构，最多三个点；相邻记录点保持原有 64 格上限。少于三个点时，缺失活动沿用女仆原有的区域回退规则。

结构绑定依次校验：记录存在且有效、维度相同、结构与锚点已加载、姿态可用、女仆由 Sable 跟踪到同一结构、距离最近活动点不超过 32 格。分别提示维度不同、结构不同、未在目标结构、过远、卸载、移除、分裂、锚点丢失等原因。校验失败保留原配置；成功后女仆获得独立副本，后续修改罗盘不会改写已经绑定的女仆。

普通世界罗盘仍保留原模组的绑定距离行为，32 格检查用于涉及结构的绑定；普通世界中在 GUI 启用已配置 Home 的距离检查仍由女仆原模组处理。

## 结构生命周期

- 平移和水平旋转不改变局部 Home。路径节点、到达判定、基础搜索中心、注视目标使用相应坐标转换。
- 方块通过 Sable 标准装配/搬移接口迁移时，按实际搬移方块更新锚点及活动点；普通世界 Home 被装配进结构也可迁移。
- 所有活动锚点一起移到同一新结构时保持有效。任意已记录锚点与其他锚点分属不同空间，整组永久失效，必须重新记录并绑定。仅活动范围跨越分裂边缘、锚点仍同属一个结构时，不会因此失效；范围内可用路径仍限于该结构。
- `UNLOADED` 仅暂停，允许加载后恢复；`REMOVED` 永久撤销旧绑定。记录存在于世界存档，因此离线女仆、箱中罗盘也能保持撤销结果，重新出现相同结构 UUID 不会恢复旧 Home。
- 收纳工具只要走 Sable 标准 `REMOVED` 流程即可通用处理；如果某附属模组绕过该接口或将收纳伪装成 `UNLOADED`，单靠 Sable 公共语义无法区分，不能承诺自动覆盖此类实现。
- 罗盘锚点失去碰撞支撑时绑定永久失效；简单 Home 支撑暂时丢失时暂停。倾斜阈值为结构局部上方向与世界上方向夹角约 10 度，超过阈值暂停，恢复后继续。
- 失效 Home 保持 Home 开关状态并停止相关 AI，不自动改为跟随。玩家可以关闭 Home、重设简单 Home，或清空并重录罗盘。物理运动、重力和伤害不被取消。

绑定账本保存在主世界 `data/tlm_sablecompat_bindings.dat`，与女仆和罗盘内的引用一起使用。不要将引用单独复制到另一存档；缺少账本时会要求重新绑定。账本保留旧配置和失效记录，当前没有清理历史条目的管理命令。

安装前已经记录、但没有结构身份的旧结构罗盘需清空重录；旧女仆 Home 建议关闭后重新设置。普通世界旧罗盘在使用时可以接入新记录机制。

## 寻路边界

复用 Sable 的结构内寻路和物理碰撞，在女仆的路径节点上限制为当前结构。甲板上属于其他结构的杂物不会加入动态绕行规划；碰到障碍时允许原有的卡住、重试行为。传送安全检查仍考虑这些杂物。

本阶段修正基础方块搜索坐标，但不等于所有女仆工作任务已经兼容。农业、容器操作、战斗、床、特殊载具与其他模组任务还可能有各自的交互距离或坐标检查，需要后续专门验证。也未实现侧墙/天花板行走、跨结构桥接路径或多结构联合导航。

## 验证

`runGameTestServer` 启动真实的 NeoForge 服务器，加载指定版本的 Sable、物理后端与女仆模组。当前 11 项 GameTest 全部通过：

1. GUI Home 底层设置、结构平移后的范围判定、结构路径生成与基础 BFS。
2. 实际拆出锚点造成活动区分离并永久失效，以及结构移除撤销记录。
3. 普通世界 Home 随方块装配进入结构。
4. 同结构、其他结构、未被跟踪及过远的绑定校验。
5. 占用落点拒绝、90 度倾斜暂停与恢复、空中无落点拒绝。
6. 罗盘非法记录与非法绑定不覆盖旧数据，女仆使用独立副本。
7. 主人飞离无落点时保留女仆的独立移动目标。
8. 未跟踪 B 时拒绝选择 B，跟踪 B 后允许跨结构传送，以及返回普通世界落点。
9. 其他独立结构占用落点时拒绝传送，移走后恢复。
10. 全组锚点迁移保持有效、卸载只暂停、完整账本序列化后保留撤销记录。
11. 平移及水平旋转后的 Brain 到达判定与注视目标投影。

测试通过 FakePlayer 和显式设置 Sable 跟踪状态构造主人场景；它们不验证真实客户端的移动包处理，也不替代长时间驾驶飞艇的游戏体验测试。尚未运行带 Create Aeronautics 或具体收纳附属模组的客户端实测。

建议游戏内按以下顺序验收：移动飞艇内慢走与跳跃 → 飞离无落点 → 登上另一飞艇 → 空中飞越第三艘飞艇 → GUI Home → 三活动区通勤 → 拆分锚点 → 卸载后返回 → 收纳再放出。另检查坐下、睡眠、拴绳和关闭 Home 时的行为。
