# 高一格掉落物拾取（0.0.1-beta）

女仆原有掉落物传感器每 30 tick 搜索一次，竖直搜索范围约为上下 4 格，因此不是简单漏搜脚部上方。实际拾取范围也是女仆身体包围盒加拾取属性范围。主要缺口在主动寻路：`MaidPickupEntitiesTask` 检查能否走到掉落物本身所在格，没有选择台面旁边低一格的站位。低顶棚阻止女仆站上台面时，物品即使可见也可能被排除。

此外，这个独立的拾取传感器和任务原先没有适配结构 Home 的局部坐标，结构上的搜索和路径目标存在坐标混用。

本次修复：

- 掉落物可从同层或低一格的可达站位拾取，不要求站上它所在的台面。普通世界与结构上均生效。
- 对高于脚部半格至约一格的掉落物，允许从水平相邻位置伸手拾取；竖直上限留有 0.25 格实体离地余量，水平范围至少覆盖一格。原有更大拾取属性仍然有效。
- 搜索和实际收取同步处理，避免“找到了、走到了，却不能收取”。普通世界原本能直接走到物品位置的路径继续跟踪实体。
- 结构 Home 搜索区域投影至世界坐标，站位和范围在结构局部坐标计算；仅在女仆允许工作的当前结构内选目标，不跨结构追逐。
- 保留拾取开关、类型筛选、掉落保护时间、库存模拟、拾取事件和正常背包写入流程；实际收取增加碰撞射线检查，不穿过楼板或墙。
- 维持原有传感器频率；复用原有邻近实体查询，并只在目标周围检查最多 18 个站位。复用已经准备好的 BFS，不嵌套创建寻路器。

新增服务器测试覆盖普通世界、旋转结构上低顶棚台面的目标搜索、低处站位、真实收取和数量，以及拾取开关、掉落保护时间、满背包及手部槽位、半砖遮挡和跨空间限制。测试不替代完整整合包客户端实测。

最终基础环境 28 项、包含附属模组的环境 45 项 GameTest 全部通过，构建成功。拾取测试采用独立批次，减少物理结构测试场景之间的干扰。
